# Шпаргалка для повторения — 40 билетов (по 1 абзацу)

> Сжатая выжимка для финального повторения: ключевое определение/формула + то, что обязательно сказать.
> Подробности — в соответствующих файлах `NN-*.md`.

**01. Закон Амдала и Густафсона.** Амдал (фикс. размер): $S=1/(a+(1-a)/p)$, $a$ — последовательная доля; предел $p\to\infty$ даёт $1/a$ (потолок: при $a=5\%$ — максимум $20\times$). Густафсон (растущая задача): $S=p-a(p-1)$ — линейный рост. Не противоречие: strong scaling (та же задача, есть потолок) vs weak scaling (задача растёт). Карп–Флэтт: если эффективная $a$ растёт с $p$ — это паразитный оверхед синхронизации, а не фундаментальный предел.

**02. SIMD.** Одна инструкция над вектором: SSE 128 бит (4×float), AVX/AVX2 256 (8×float), AVX-512 512 (16×float) + маски `k0..k7`. Три пути: интринсики, автовекторизация, портируемый `std::simd` (C++26). Обязательны: выравнивание (кэш-линия 64 Б), обработка **хвоста** (n не кратно ширине), осторожно со штрафом AVX↔SSE (`vzeroupper`) и снижением частоты на AVX-512.

**03. Процесс.** Экземпляр программы со своим виртуальным адресным пространством, дескрипторами, PID. В Linux — `task_struct` («задачи», нет жёсткого деления процесс/поток). Создание: `fork` (копирование адресного пространства через **Copy-on-Write** — страницы read-only, копируются при записи page-fault'ом), `clone`, образ заменяет `execve`. Завершившийся без `wait` родителя — **зомби**; осиротевший усыновляет PID 1.

**04. Поток.** Единица планирования внутри процесса: общие адресное пространство/куча/дескрипторы, но свой стек/регистры/TLS/приоритет. Linux — модель **1:1** (NPTL), `clone` с `CLONE_VM|CLONE_THREAD|…`, общий PID/TGID, разные TID. Переключение дешевле процесса (не меняется `CR3`, TLB цел). C++20: `std::jthread` (авто-join + кооперативная отмена через `stop_token`); `std::thread` без join → `terminate`.

**05. IPC.** 8 механизмов: файлы/mmap, pipe/FIFO, сокеты (Unix-domain умеют передавать **fd** через `SCM_RIGHTS`), **shared memory** (самый быстрый — нет копирования через ядро, но **не несёт синхронизации**), сигналы (асинхронное уведомление-номер, только async-signal-safe в обработчике), семафоры, D-Bus (шина сообщений Linux), оконные сообщения (Windows). SHM + семафор — классическая быстрая связка.

**06. Потоки vs процессы. TLB.** **TLB** — кэш переводов «виртуальный→физический»; промах = дорогой page walk. Переключение процесса меняет `CR3` → TLB невалиден (исторически flush); потока — `CR3` тот же, TLB цел → дёшево. **PCID/ASID** — теги адресного пространства, позволяют не сбрасывать TLB. KPTI (после Meltdown) удорожил переходы user↔kernel. Процессы — изоляция/надёжность, потоки — скорость/общая память.

**07. Семафор.** Счётчик $S\ge0$ (Дейкстра): `P`/acquire — `while(S==0) wait; S--`; `V`/release — `S++; разбудить`. Инвариант $S=S_0+V-P\ge0$. Бинарный/считающий. Ключевое отличие от мьютекса — **нет владельца**: `V` может вызвать другой поток (сигнальная семантика), нет наследования приоритета. Быстрый путь — CAS в userspace, медленный — `FUTEX_WAIT/WAKE`.

**08. Завершение потока.** `join` — блокирующее ожидание + сбор ресурсов (TCB/стек), иначе «зомби»-поток. `pthread_cancel` — не убивает сразу: ставит флаг (через внутренний `SIGCANCEL`), срабатывает в **точках отмены** (read/write/wait/…), разворачивает стек через cleanup-обработчики; async-отмена опасна. В C++ принудительной отмены нет — только **кооперативная** через `stop_token` (+ `condition_variable_any` для прерывания сна).

**09. Семафор и барьер.** Барьер: $N$ потоков `arrive_and_wait()`, никто не идёт дальше, пока не пришли все. `std::latch` — одноразовая защёлка (`count_down`/`wait`); `std::barrier` — переиспользуемый (фазовый) + completion-функция один раз на фазу. Устройство: нужен **счётчик поколения** (иначе гонка переиспользования) — реализуется **sense-reversing** барьером (чередующийся бит `sense`).

**10. Синхронизация списка на 2 потоках.** Множество на отсортированном списке с сентинелами ±∞. Минимум — один мьютекс (грубо, сериализует). Фундаментальная гонка: одновременные `remove(b)` и `remove(c)` при недостаточной синхронизации теряют узел `c` (обновление `b.next` уходит в отцепленный узел). Отсюда нужда удерживать **два** лока (билет 15). Плюс проблема безопасного освобождения узлов, читаемых без локов.

**11. Мьютекс.** Взаимное исключение **с владельцем** (отпускает тот, кто захватил). `lock/unlock/try_lock`; `scoped_lock(a,b)` берёт несколько без deadlock. Linux — поверх **futex**, протокол **трёх состояний** (0 свободен/1 занят/2 есть ожидающие) — третье состояние, чтобы `unlock` не делал лишний syscall. Рекурсивный = TID+счётчик (запах дизайна, лечится приватным «ядром» без лока). `shared_mutex` = RW-lock (много читателей/один писатель, возможна голодовка писателя).

**12. Условные переменные.** Ждать условие: `wait(lock,pred)` атомарно отпускает мьютекс и спит; будит `notify_one/all`. **Предикат в цикле обязателен** — защита от (а) spurious wakeup (пробуждение без notify; источники — сигналы, `FUTEX_REQUEUE`), (б) lost wakeup (notify до wait теряется), (в) нескольких потребителей. Атомарность «release+wait» через sequence-счётчик futex. `notify_all` → «громовое стадо», смягчается requeue на futex мьютекса. `if` вместо цикла — классический баг.

**13. Системный вызов.** Контролируемый переход user (ring 3) → kernel (ring 0). x86-64: номер в `rax`, аргументы `rdi,rsi,rdx,r10,r8,r9` (r10, т.к. `syscall` затирает `rcx`/`r11`), инструкция `syscall` (точка входа в MSR `LSTAR`, селекторы `STAR`, маска `FMASK`), `swapgs` + смена ядерного стека, диспетчер `sys_call_table`. `errno` ставит обёртка libc (`-errno` в `rax`). **vDSO** — время без перехода в ядро; **KPTI** — трамплин со сменой `CR3`. Идея futex/io_uring — минимизировать syscalls.

**14. CAS.** Атомарно: если `*addr==expected`, записать `desired`, иначе вернуть текущее. x86 — `LOCK CMPXCHG` (cache locking, а не bus lock; невыравнивание → дорогой **split lock**); широкий — `cmpxchg16b`. ARM — LL/SC (`ldxr`/`stxr`, эксклюзивный монитор) → `stxr` ложно проваливается → **weak** CAS (всегда в цикле) vs **strong**. Универсальный примитив (консенсус ∞). Применения: spin-mutex (TTAS+`pause`), `atomicMax`. Опасность — ABA.

**15. Грубая и тонкая синхронизация.** Грубая — один лок на структуру (просто, сериализует). Тонкая — лок на узел, обход **hand-over-hand** (lock coupling): держим **два** соседних лока, отпускаем `pred` только после захвата следующего. Два лока нужны, т.к. для перелинковки меняется `next` у `pred` (доказательство через сериализацию конкурентных `remove` на общем узле). Deadlock-free (единый порядок head→tail), но зависший под локом блокирует идущих позади.

**16. Оптимистичная синхронизация.** Искать `pred`/`curr` **без локов**, потом залочить оба и **валидировать** — заново пройти от head: `pred` достижим И `pred.next==curr`. Ловит две гонки: `pred` стал недостижим (узел добавится в отцепленный сегмент) и вставка между `pred`/`curr` (удалятся два узла). Ставка: двойной обход без локов дешевле прохода с локами. Deadlock-free, но **не** starvation-free; `contains` тоже лочит; нужен reclamation.

**17. Ленивая синхронизация.** Как оптимистичная + бит `marked` (логическое удаление отделено от физического): `remove` сначала помечает, потом отцепляет. `contains` — **wait-free**, без локов и валидации (просто проверяет `marked` и порядок ключей). Валидация O(1): `!pred.marked && !curr.marked && pred.next==curr`. Точки линеаризации: `add` — установка `pred.next`; `remove` — установка бита `marked`. `add`/`remove` всё ещё блокирующие; нужен reclamation.

**18. Неблокирующий список (Харрис–Майкл).** Только CAS: `add`/`remove` lock-free, `contains` wait-free. Бит `marked` **атомарно вшит в указатель** `next` (младший бит выровненного адреса) — иначе CAS-вставка «проскользнёт» в логически удалённый узел. `remove` = CAS-пометка (логически) + CAS-отцепление (физически, best-effort). `find` — рабочая лошадка, попутно вырезает помеченные узлы, рестартует при гонке (только если кто-то продвинулся → lock-free). Обязателен reclamation + защита от ABA.

**19. Deadlock.** Циклическое ожидание ресурсов. Условия Коффмана (все 4): взаимное исключение, hold-and-wait, no-preemption, circular wait — убрать любое = нет deadlock. Виды: простой (повторный захват нерекурсивного мьютекса), перекрёстный (T1: A→B, T2: B→A), при `fork` (мьютекс остаётся «навечно занят» исчезнувшим потоком → после fork только `exec`/`pthread_atfork`). Профилактика: единый порядок захвата, `scoped_lock(a,b)` (try-and-back-off).

**20. Гонки.** **Data race** — неатомарный общий доступ с записью без happens-before → **UB** (не «иногда неверно», а отравляет всю программу: torn reads, переупорядочение). **Race condition** — корректность зависит от тайминга, бывает **без** data race (атомарный «проверить-и-действовать»). **API race/TOCTOU** — гонка между корректными по отдельности вызовами (`if(!v.empty()) v.back()`). `volatile` не синхронизирует. Инструмент — TSan (shadow memory + vector clocks).

**21. Инверсия приоритетов.** H блокируется на мьютексе, удерживаемом L, а L вытесняется среднеприоритетной M (на ресурс не претендующей) → H ждёт неограниченно. Не deadlock (прогресс есть, но не у того). Решения: **наследование приоритета** (L поднимается до H, пока держит ресурс — есть владелец, потому работает; семафор не умеет) и **потолок приоритета**. Кейс **Mars Pathfinder**: inheritance был выключен → watchdog-перезагрузки; чинили в полёте.

**22. ABA.** Поток читает A, конкурент делает A→B→A, и CAS «успешен», не заметив изменений → повреждение (особенно с переиспользуемыми указателями; пример — `pop` стека Трайбера теряет узлы). Борьба: версионный/tagged указатель (`cmpxchg16b`), **hazard pointers** (поток публикует защищаемый указатель → узел не освобождают, пока есть hazard; retire+scan), epoch/RCU, GC. ABA и safe reclamation — две стороны одной медали. C++26 `std::hazard_pointer`.

**23. Атомарный снимок (lock-free).** `update(i,v)` в свою ячейку + `scan()` — мгновенный согласованный снимок всего массива. Lock-free = **double collect**: прочитать массив дважды; если оба сбора совпали — валидный снимок (никто не писал между ними). Нужны **порядковые номера** на ячейках (иначе ABA на значениях: $v\to w\to v$ даст ложное совпадение). Только lock-free: при непрерывных `update` `scan` может голодать.

**24. Атомарный снимок (wait-free).** Каждый `scan` завершается за ограниченное число шагов через **helping**: писатель **перед** записью сам делает `scan` и **встраивает** его в ячейку. Сканирующий, увидев, что писатель сдвинулся **дважды** за его интервал, понимает — тот выполнил полный `update` внутри, и **заимствует** его встроенный (чистый) снимок. После ≤O(n) помех `scan` завершается. Цена: писатель тоже сканирует, память O(n)/ячейку. Helping — общий мост lock-free→wait-free.

**25. MESI.** Когерентность кэшей: линия в M (изменена, эксклюзивна, грязная) / E (чистая, эксклюзивна) / S (разделяема) / I (невалидна). Сообщения: Read, Read Response, Invalidate, Invalidate Ack, Read Invalidate, Writeback; запись = RFO (инвалидировать чужие копии). **Store buffer** (запись не ждёт RFO, store forwarding → store→load reordering) и **invalidate queue** (отложенные инвалидации) дают скорость, но ломают порядок → нужны барьеры. Когерентность ≠ согласованность. False sharing.

**26. Переупорядочение памяти.** 4 типа: LoadLoad, LoadStore, StoreLoad, StoreStore. Read-барьер осушает invalidate queue, write-барьер сливает store buffer, full (`mfence`) запрещает и StoreLoad. **Acquire** (на load) не пускает последующее вверх; **release** (на store) не пускает предыдущее вниз; пара release→acquire даёт happens-before (публикация данных через флаг), но StoreLoad не запрещён (для Петерсона нужен seq_cst). **x86-TSO**: единственное переупорядочение — store→load → acquire/release «бесплатны» на x86 (но ломается на ARM). `consume` мёртв.

**27. Стек Трайбера.** Lock-free LIFO: `top` — атомарный указатель, `push`/`pop` через CAS-петлю. `push`: новый узел → текущий `top`, `CAS(top: old→new)`. `pop`: `CAS(top: t→t.next)`. Lock-free (рестарт только если другой продвинулся), не wait-free. Точка линеаризации — успешный CAS. `release` на push / `acquire` на pop. Главные беды: **ABA** в `pop` и нельзя `delete` без reclamation. Под контеншном — cache-line bouncing на `top`; лечит elimination-backoff.

**28. Очередь Майкла–Скотта.** Lock-free FIFO с **dummy-узлом**, раздельными `head`/`tail`. `enqueue` — **два CAS, не атомарных вместе** (`tail.next: null→n`, затем подтянуть `tail`) → `tail` может отставать на один; любой поток **помогает** (helping) подтянуть. `dequeue` читает head/tail/head.next, различает «пусто» и «tail отстал», читает значение **до** CAS head. Точки линеаризации: enq — первый CAS, deq — CAS head. ABA (counted pointers), reclamation.

**29. Линеаризуемость.** Объект линеаризуем, если каждая операция «происходит мгновенно» в **точке линеаризации** между вызовом и ответом, и итог = легальная **последовательная** история, не нарушающая реальный порядок непересекающихся операций. Формально L1 (эквивалентна легальной последовательной) + L2 (сохранён реальный порядок завершившихся). Свойства: **локальность/композируемость** (система из линеаризуемых объектов линеаризуема) и неблокирующность. Строго сильнее sequential consistency (= без L2, не композируема).

**30. RCU в ядре.** Много читателей + писатель без блокировки чтения: писатель **публикует новую** версию, старую освобождает после **grace period** (когда все читатели, начавшие до публикации, завершились). Три части: publish-subscribe (`rcu_assign_pointer`/`rcu_dereference`), ожидание читателей (`synchronize_rcu`/`call_rcu`), несколько версий. На `CONFIG_PREEMPT`-off `rcu_read_lock` **пуст**; grace period = каждый CPU прошёл quiescent state (context switch/idle/user). RCU ≈ масштабируемый RW-lock; писатели тяжелее, latency мс.

**31. RCU в user-space.** Нет рычага планировщика → вводят **глобальную эпоху**: читатель копирует её в локальную, писатель инкрементирует и ждёт, пока все покинут старую. Писатель **обязан знать** читателей (регистрация потоков). Варианты: QSBR (быстрейший, явные quiescent state), mb, signal. libcds: однобитная эпоха + счётчик вложенности → `flip_and_wait` вызывается **дважды** (копирование atomic→atomic не атомарно, после двух переворотов бит возвращается → устаревшая эпоха «выглядит актуальной» → ждать на обеих чётностях). C++26 `std::rcu`.

**32. Flat combining.** Вместо «все лезут в структуру под локом» — потоки **публикуют запросы** в список (через TLS-записи); один **combiner** берёт единственный лок и **последовательно** применяет все чужие запросы. Снижает контеншн/cache-bouncing, использует горячий кэш одного потока. «Synchronization-parallelism tradeoff»: один последовательно, но без синхронизации, обгоняет параллельное под высоким контеншном. Превращает последовательную структуру (стек/очередь/PQ) в конкурентную. При низком контеншне — лишний оверхед.

**33. Транзакционная память.** Критические секции как атомарные транзакции: спекулятивно, с откатом при конфликте (read-set/write-set), иначе атомарный commit. **HTM** (Intel TSX): HLE (`XACQUIRE/XRELEASE` — элизия лока, совместимо) и RTM (`XBEGIN/XEND/XABORT`), отслеживание по кэш-линиям, **обязательный fallback** на лок, аборт по конфликту/ёмкости/I-O. **STM** — программная, высокий оверхед. Плюсы: простота, композируемость, нет deadlock. TSX отключён микрокодом (TAA).

**34. Консенсус.** Задача: все потоки договариваются об одном из предложенных значений, wait-free. **Консенсусное число** объекта = макс. $N$, для которого из него (+ регистры) строится wait-free консенсус. Иерархия Херлихи: регистры = 1 (доказательство через бивалентность), test&set/fetch&add/стек/очередь = 2, **CAS/LL-SC = ∞** (универсальны — из CAS строится wait-free любой объект). Поэтому CAS кладут в ISA. Нюанс: иерархия не робастна (комбинация CN=1 над одной ячейкой может дать ∞).

**35. Асинхронный I/O.** Две оси: sync/async (кто ждёт завершения) и blocking/non-blocking (возвращает ли сразу). **Readiness** (`select`/`poll`/`epoll`) — ядро говорит «можно читать», читаешь сам; **completion** (IOCP/io_uring) — отдал операцию, уведомят о завершении. `select`/`poll` — O(n) скан всех fd (C10k); `epoll` — регистрация раз + O(1) ready-list, LT/ET; io_uring — кольца SQ/CQ, батч, +файлы. ET → читать до `EAGAIN`.

**36. Async-движки (Полухин).** Синхронный сервер (поток на соединение): блокирующие read/write = syscall + сон, тысячи потоков = память на стеки + тысячи context switch → C10k. Асинхронный: event loop (epoll/io_uring) + неблокирующие сокеты + **лёгкая корутина** на соединение (не поток); `co_await` подвешивает **корутину**, не поток (маленький frame, переключение в userspace). Корутины дают «линейный» вид асинхронного кода. Stackful-fiber нельзя мигрировать между потоками (кэширование TLS). Async не ускоряет CPU-bound.

**37. Пул потоков.** N заранее созданных воркеров разбирают задачи из очереди (амортизирует дорогое создание потоков, нет переподписки). Наивно: очередь + мьютекс + CV + `stop_token`-shutdown; задачу выполнять **вне** лока; узкое место — контеншн на единой очереди. Промышленно — **work-stealing**: своя deque на воркера, свои задачи LIFO, кража чужих FIFO (горячий кэш своим, крупные старые задачи вором). Размер ≈ ядрам (CPU) / больше (I/O). Опасность — deadlock через пул.

**38. Декомпозиция по данным.** Одна операция над разными частями данных (SPMD). Разбиение: блочное (локальность), циклическое (баланс), блочно-циклическое, геометрическое (домены). `std::execution::par_unseq` (потоки × SIMD). Балансировка статическая (однородная нагрузка) / динамическая (неоднородная). Аппаратно: **NUMA first-touch** (инициализировать данные тем же потоком, что обрабатывает) и **false sharing** на стыках чанков (выравнивать). Нижний уровень — SIMD, предел — GPU.

**39. Декомпозиция по задачам.** Программа = разные задачи; зависимости = **DAG** (ацикличный). Для нерегулярных вычислений (рекурсия, обход дерева). Модель **fork-join**: породить подзадачи + дождаться. Рантайм — work-stealing пул. **Cutoff** — порог перехода на последовательный код у листьев (иначе оверхед мелких задач). Ловушки: `std::async(launch::async)` без сохранения future **блокирует** в деструкторе (сериализует); deadlock через исчерпанный пул; циклы в DAG.

**40. Dataflow.** Вычисление = граф: узел срабатывает, когда **готовы входы**; явного управляющего потока нет, параллелизм из зависимостей данных. Частный случай — **конвейер**: стадии работают одновременно над разными элементами → растёт **пропускная способность**, но **не латентность** одного элемента. Реализация: ограниченные очереди с **backpressure** (медленная стадия притормаживает быструю, нет роста памяти). Bottleneck — самая медленная стадия (реплицировать). C++26 senders/receivers.
